# 真实视觉 · Truesight

Truesight 对 Foundry 条目进行聚类，并利用已确认的成员关系汇集名称证据。dnd5e 已知 Item 类型按各自身份约束生成候选，职业特性同时核对所属职业／子职和前置等级；名称解析也支持尚未归组的独立条目。插件不修改文档、角色卡或自动化。

## 使用

依赖 Quick Insert 3.7.8 或以上，不依赖 Slow Insert、中文汉化包、CPR 或 GPS。将发行包中的 `truesight` 目录安装到 `Data/modules`，启用后重启 Foundry 服务并重新载入客户端，使模块通信声明生效。

GM 在「配置设置 → 真实视觉 · Truesight → 审核规则分组」打开管理窗口。默认查看已应用的归组；点击「重新计算」生成完整索引的候选，再在固定底栏点击「应用变化」。风险后缀归并默认关闭；预览、关闭窗口和普通索引刷新都不会发布成员关系。停用 Slow Insert 后，管理入口及中文适配仍可工作。

审核保存在当前世界的原生世界设置中，所有客户端共享同一修订；GM 不在线时仍可读取。GM 可以打开管理窗口，玩家只使用权限范围内的分组与名称结果，不提供审核入口、管理操作和撤销记录。首选、收藏、隐藏和筛选仍是个人偏好。每次写入保留一层撤销；撤销产生新修订。

发布由 Foundry 选定的在线主 GM 负责，并要求其具有世界设置写权限；其他 GM 可以查看和预览。同一主 GM 打开多个客户端时暂停发布，关闭多余客户端后继续。异常断线导致客户端记录残留时，关闭多余客户端并重新载入剩余客户端。保存期间拒绝第二次修改；预览基于旧修订或证据变化时需重新计算。

首次建立世界审核时，点击「重新计算」，检查候选后再应用。审核缓存版本或结构无效时立即报错并停用缓存；取得发布资格的 GM 客户端自动清空世界审核、撤销记录和身份排除。清理完成后重新计算。

新增条目先独立；已删除或不可访问的成员不返回；当前索引缺项不删除世界审核，缺少成员的旧组保留原审核决定，直到能够完整复核；身份字段变化的成员失效。仅改特性或法术的显示译名不会单独使普通分组失效；职业、子职、种族和背景的名称若用于核对 requirements，则属于身份依据。2014 与 2024 分开，聚类不读取名称解析结果来证明身份。独立条目可按原因筛选，详情显示类型、所属对象、前置等级或来源文档。

### 检查归组与人工排除

Slow Insert 的组级「检查归组…」打开此窗口，并以成员 UUID 定位完整的当前归组；搜索面板的个人筛选不缩小这里的核对范围。窗口只读取已有审核，不自动重算或发布。目标已独立时定位该条目；目标不在可见索引中时明确提示。

人工排除用于暂时隔离需要单独处理的条目。展开成员卡的「身份管理（高级）」，点击「预览排除该条目…」，核对操作对象、当前成员、应用后的成员关系及世界共享影响，再点击底栏「应用变化」。取消或关闭窗口不会写入。排除按 UUID 持续生效，后续重新计算也保留；它影响所有客户端的归组与名称解析，不修改文档，也不等于确认两个内容不同。

在「更多操作 → 已排除条目」选择一个条目，展开高级操作并点击「预览恢复该条目…」。恢复只解除选中条目的排除，其他排除保持不变。仍有效的原归组可在应用后恢复；如果重新计算或证据变化已使原关系失效，预览会说明条目仍独立，需要另行重算审核。系统不再提供一次恢复全部排除的入口。

预览不会授予发布权限；非发布 GM 可查看和预览，由具备发布资格的客户端应用。成员不可见、受影响组不完整、证据或审核修订变化时拒绝旧预览，保存失败保留原审核。最近一次应用仍可通过「撤销上次归组」撤回。

### 同名待核对

点击「同名待核对」查看缺少充分分开依据的同名集合。列表同时包含已审核组与组外副本，并统计集合数及涉及条目数。选择集合后，先比较逐对关系，再查看各条目、原有分组、名称证据和身份字段。职业、获得等级及字段冲突都保留为核对线索；未知代际不会连接两个已确定的规则代际。

点击逐对关系中的「对照规则内容」，按需读取双方规则正文；窄窗口改为上下排列。原生条目另列使用次数、恢复配置及可见职业条目的 ScaleValue 成长配置，并保留来源。正文措辞、译文或自动化配置差异仅供对照；核对规则本身后再填写依据，不自动判定不同内容。

启用 Plutonium CN 且其数据接口可用时，Truesight 读取职业、职业特性和子职特性的 UID、来源、英文原名、所属对象与规则代际，纳入现有身份规则。无需增加依赖或修改 CN。接口不可用或身份字段冲突时，相关条目保持独立并显示原因；原来的打开、拖放和导入操作保持不变。重新载入后，等待身份读取完成，再重新计算并应用新增候选。

填写比较依据后，选择「同一内容：预览归组」或「不同内容：预览确认」。预览列出双方完整组的影响范围与差异；点击「应用变化」后才发布。确认不同内容时，一次决定覆盖两个明确列出的侧面，无需逐个重复确认已有组中的副本。暂不处理时保留在列表即可。排除归组不等于确认不同内容。

「更多操作 → 查看核对决定」可查看已保存依据、证据是否变化，并预览撤销指定决定；「撤销上次归组」也可撤销最近一次核对发布。新副本或证据变化会重新产生待核对关系。仅由轻量空白、大小写或全半角变化造成的名称差异不改变名称证据。

## API v1

运行时入口：

```js
const {apiVersion, catalog, names, sources} = game.modules.get('truesight').api;
if (apiVersion !== 1) throw Error('Unsupported Truesight API');
await catalog.whenReady();
const view = catalog.read();
const member = catalog.getMember('Compendium.package.pack.Item.id');
```

也可从公开的 `modules/truesight/api-v1.mjs` 导入同一 API；该路径须保留 Foundry 的部署前缀。`scripts/` 是内部实现，消费者不应导入。`sources` 提供书目和来源解析；`names` 的纯解析函数与加载契约见工作区架构说明。

### 目录与状态

- `getStatus()`：轻量状态查询，不执行 QI 搜索；返回 `apiVersion`、`ruleVersion`、`revision`、`generation`、`revisions`、`scope: "world"`、`reviewed`、`canManage`。GM 另有 `canPublish`、`publishReason`、`publisherId`、`canUndo`、`includeRisk`。
- `status` 区分 `not-ready`、`ready`、`unreviewed`、`unavailable`、`failed`。未审核成功返回独立条目；读取失败抛出带 `code`/`source` 的错误，不伪装成空组。
- `whenReady({timeout})`：等 Quick Insert 索引完成，默认 60 秒；超时、被 GM-only 限制、接口不支持或审核损坏均明确拒绝。
- `read(uuids?)`：返回同一审核修订下的 `entries: Map`、`groups: Map`、`changed` ；GM 另有可见排除数量。成员包含类型、代际、状态、理由与来源证据，不含搜索包装、UI 对象或文档方法。指定 UUID 时，组成员仍是该组当前可访问的全部成员；未索引的查询条目标为 `not-indexed`，不会自行推断其归属。
- `getMember(uuid)`：读取一个成员。成员状态包括 `member`、`independent`、`pending`、`invalidated`、`conflict`、`not-indexed`，细分原因在 `warning`/`reason`。原因区分等待审核、无匹配、身份信息缺失、上下文差异／冲突、人工排除、旧组缺项及未知类型；已知类型缺证据时使用具体的缺失原因。

### 审核与扩展

审核窗口、预览与所有管理操作只向 GM 开放；写入还需通过发布客户端及原生世界设置权限检查。底层世界设置不提供额外加密或严格保密。

- `preview({includeRisk})`：生成本客户端预览，返回预览 `id`、差异、成员、独立条目和保留的缺项数量。
- `readNameReview({previewId}?)`：读取当前或指定预览的同名待核对集合、集合数与去重条目数。
- `readNameSet(key, {previewId, offset, limit}?)`：读取集合名称证据、已有组与逐对字段比较；关系每页默认 25 对，上限 100 对，待核对关系优先。
- `loadRuleEvidence(uuids)`：GM 按需读取至多 50 个当前可见条目的规则正文、实现配置与成长来源；异步完成后复核权限和修订。虚拟导入条目只读提供方数据，不调用导入或文档实例化入口。结果为独立副本，不发布成员关系。
- `readNameDecisions()`：读取成员全部可见的核对决定、双方范围、依据与当前证据状态。
- `previewNameDecision({left, right, kind, reason})`：`kind` 为 `same` 或 `different`，UUID 为规范格式，`reason` 为非空核对依据。展开所选条目的完整审核组，生成含影响成员和冲突的预览；每次至多 500 个成员，单成员证据至多 12,000 字符，依据至多 1,000 字符。
- `previewNameDecision({kind: "revoke", key})`：预览撤销指定决定；不会顺带批准其他候选组。
- `apply(id)`：确认预览；证据或审核已改变时拒绝应用。
- `undo()`：撤销最近一次共享审核修改。个人隐藏和首选由消费者另存。
- `previewExclusion({uuid, excluded})`：预览单条身份排除（`true`）或解除排除（`false`），返回标准预览及 `exclusion` 的操作对象、受影响成员、前后关系和 `restored` 状态。通过 `apply(id)` 明确发布；不重算其他组，不批准新关系。原立即写入的 `exclude` 与批量恢复的 `restoreExcluded` 接口已移除。
- `openReview({memberUuid}?)`：打开独立管理入口；可携带规范成员 UUID 定位当前完整组或独立条目。只定位，不修改审核；目标缺失明确提示。
- `registerPublications(id, records)` / `unregisterPublications(id)`：共享书目扩展。返回的注销函数只撤去本次注册，不会删除后来的同名替换。
- 声明式书目使用 `flags.truesight.publications`。
- `sourceEnvironment()`：当前来源解析上下文，供搜索展示等消费者使用。

监听 `Hooks.on('truesightChanged', change => ...)` 刷新受影响的派生结果。`change.changes` 列出 `identity`、`names`、`access`、`sources`、`review`、`display` 领域；`publication` 仅通知管理界面的发布资格变化；`catalog.affects(change, domains)` 和 `names.affects(change, domains)` 判断是否相关，通知必须提供 changes 领域集合。身份、权限、来源和审核变化同时影响名称。普通生命值、资源消耗及窗口偏好不发通知；普通名称和图片更新保留普通审核预览；风险规则及同名核对预览将名称更新视为相关证据变化。相关变化立即作废服务实例内的预览；普通通知合并到下一轮事件循环，权限变化立即通知。通知只带状态、修订及领域，不广播成员 UUID、名称或来源。每次读取重新按权限检查并验证已应用快照，普通刷新不自动扩大已确认组。

## 名称能力与失败

`names.apiVersion` 为 1。名称层读取可见索引、独立名称证据和 `catalog` 的有效成员关系，按消费者自己的候选目录消歧。没有中文汉化包时不读取其资产，仍可使用索引中的原名和双语名；汉化包已启用但读取失败则报告失败，不发布不完整结果。

CPR/GPS/MISC 适配监听相关证据变更重建计划；重建前先撤下旧派生结果。CPR 只撤回由本适配注册且尚未被其他代码改写的键；GPS 重建期间保留原生查找。基座不依赖或调用提供方的自动化入口。

## v0.1.2：审核工作台

- 当前归组与待审核预览分开；打开窗口不重新计算。预览默认只看变化，可切换新增、成员调整、解散、需注意或独立条目。
- 左侧每页最多 50 项，右侧显示成员、来源、规则代际和判断依据；调整项展示应用前后。搜索覆盖名称、标识和来源文本。UUID 收入技术详情并可复制。
- 计算选项提供风险归组开关；更多操作提供撤销、查看排除成员与恢复排除。保存与放弃预览在固定底栏；索引或审核改变时作废预览。
- 审核仍按当前客户端保存，本次仅调整管理体验，不修改聚类规则或现有审核数据。

## v0.1.9：类型身份与职业特性

- 聚类覆盖当前 dnd5e 的全部 14 种 Item 类型及系统声明的扩展 Item 类型。职业特性归一 requirements、结构化前置条件与职业／子职的 ItemGrant；ItemChoice 不作为专属归属依据。
- 武器、装备、消耗品等按类别、子类、基础物品、稀有度和魔法加值区分变体；子职核对所属职业。法术继续核对环阶和学派，风险书目后缀规则只用于法术。
- 其他已知索引文档使用明确的同源文档证据，不凭同名或物品规则合并。证据不足保留独立条目并提供具体原因；未知类型仅表示未声明的协议类型。
- 所有索引条目进入审核记录和独立原因统计，当前列表与预览采用同一原因语义。详情补充类别、归属、前置等级与来源文档；Slow Insert 复用基座原因文案。
- 聚类规则版本升至 2，API 仍为 v1。旧版或无效审核直接报错并清空，删除旧客户端审核导入和旧通知回退。更新后所有客户端重新载入，由 GM 重新计算并应用审核。

## v0.1.13：归组检查与单条排除审核

接收搜索界面的成员上下文并定位完整归组，将人工排除收拢至成员卡的高级操作。排除与逐条恢复统一经过影响预览、明确应用及发布校验，移除立即排除和批量恢复路径。解除排除后没有有效原组时，条目标为等待审核，避免残留“已排除”状态。

本次保留人工排除的 UUID 隔离语义；同组成员的关系拆分仍需后续设计，不以人工排除替代“确认不同内容”。
